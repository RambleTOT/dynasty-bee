# Защита сайта и сервера

Сайт `bee-dynasty.ru` и API `api.bee-dynasty.ru` работают на одном сервере `185.166.196.106`. Состояние на 28.09, 13:15.

## Что уже сделано (сайт)

Конфиг — `deploy/nginx/bee-dynasty.conf`, выкладка — `scripts/deploy-nginx.sh`: резервная копия, `nginx -t`, при ошибке откат.

| Защита                                                     | Как                                                                                                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Поток запросов к API                                       | не больше 20 запросов/с с одного IP (всплеск до 40), дальше — `429`                                                                                                  |
| Тяжёлые запросы (план, сравнение, событие, запись, импорт) | все POST/PATCH — не больше 60 в минуту с IP (всплеск 20): каждый запускает солвер                                                                                    |
| Перебор пароля                                             | вход — 10 попыток в минуту с IP (всплеск 5)                                                                                                                          |
| Много соединений, медленные клиенты                        | 40 соединений на IP; таймауты заголовков 10 с, тела 20 с; тело запроса до 1 МБ (CSV — до 10 МБ)                                                                      |
| Удаление данных                                            | `DELETE` и `PUT` через сайт закрыты (`403`); фронт их не использует                                                                                                  |
| Внедрение скриптов, кликджекинг                            | Content-Security-Policy (скрипты только свои и Яндекс Карт), `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff`, HSTS, Referrer-Policy, Permissions-Policy |
| Сканеры                                                    | `/.env`, `/.git` и другие скрытые файлы — `404`; версия nginx скрыта                                                                                                 |

Проверено 28.09: вход — после 7 попыток `429`; 60 параллельных POST — 35 получили `429`; все экраны трёх ролей работают без нарушений CSP (карта, тайлы OSM, шрифт, ссылки в Яндекс Карты). Встроенная карта Яндекса загружается в режиме `csp=true` — в CSP её домены уже разрешены.

## Что нужно сделать на сервере и в бэке

Это не код фронта: настройки системы сервера и бэка. Шаги 1–4 — сегодня.

### 1. SSH перебирают прямо сейчас — P0

Вход `root` по паролю открыт (`PasswordAuthentication yes`, `PermitRootLogin yes`), за последние сутки — **20 130 неудачных попыток** входа с десятков IP. fail2ban не установлен.

```bash
ssh -i ~/.ssh/beeline_deploy root@185.166.196.106 'bash -s' < deploy/security/harden-server.sh
```

Скрипт ставит fail2ban (бан IP после 5 неудачных входов за 10 минут и за поток `429` на сайт) и включает файрвол: наружу только 22, 80, 443, 8443, 9443 и мониторинг хостинга на 10050. Вход только по ключу — тот же скрипт с `SSH_KEY_ONLY=yes`, но **сначала** ключи всех, кому нужен доступ (в том числе бэкендера), должны лежать в `/root/.ssh/authorized_keys`:

```bash
ssh -i ~/.ssh/beeline_deploy root@185.166.196.106 'SSH_KEY_ONLY=yes bash -s' < deploy/security/harden-server.sh
```

### 2. Данные стенда может стереть любой — P0

На стенде `ALLOW_DESTRUCTIVE=true`, а пароль демо-учёток — тот, что открыто написан в описании Swagger (`/docs`) и в гайде бэка. Значит, любой может войти диспетчером и вызвать `DELETE /api/v1/data/scenarios` и `DELETE /api/v1/events` напрямую в `api.bee-dynasty.ru`: сайт `DELETE` уже не пропускает, но API открыт и сам по себе.

В `/root/beeline_rps/.env`: `ALLOW_DESTRUCTIVE=false`, новый `DEMO_PASSWORD` и новый `JWT_SECRET` — иначе токены, выданные по старому паролю, работают ещё 21 день. Пароль убрать из описания Swagger (`app/main.py`, `_DESCRIPTION`) и из гайда, проверяющим передать отдельно. После смены всем, включая команду, нужно войти заново.

### 3. Бэк открыт наружу мимо nginx — P0

Порт API опубликован на все адреса: `http://185.166.196.106:8000` отвечает без TLS и без лимитов. В `/root/beeline_rps/docker-compose.yml` у `api`:

```yaml
ports:
  - '127.0.0.1:8000:8000'
```

Docker открывает опубликованные порты в обход файрвола, поэтому закрыть 8000 может только эта правка.

### 4. Перезапуск бэка

Шаги 2 и 3 и исправления бэка по `docs/BACKEND_REQUESTS.md` (код 11:29 уже лежит в `/root/beeline_rps`, коммит `b0c6195`) вступят в силу после перезапуска:

```bash
cd /root/beeline_rps && docker compose up -d --build api
```

Проверка: `curl -m 5 http://185.166.196.106:8000/health` — нет ответа; `curl https://api.bee-dynasty.ru/health` — `200`.

### 5. Лимиты для api.bee-dynasty.ru — P1

API открыт напрямую (Swagger доступен всем), и лимиты сайта его не защищают. Зоны лимитов уже объявлены в nginx — в конфиг API нужно добавить несколько строк, они в `deploy/nginx/api-limits.conf`. Там же — `server_tokens off` и таймауты. Проверка и применение: `nginx -t && systemctl reload nginx`.

### 6. DDoS по каналу — P1

nginx защищает от потока запросов (L7), но не от забивания канала (L3/L4): сайт и API на одном IP без внешней защиты. Нужна защита у провайдера:

- в панели хостинга — услуга «Защита от DDoS» (судя по адресам мониторинга, хостинг — Timeweb);
- или прокси с защитой: DDoS-Guard (российский) или Cloudflare. Для этого DNS `bee-dynasty.ru` и `api.bee-dynasty.ru` направляются на прокси, а на сервере разрешаются только его адреса.

### 7. Мелочи — P2

- CORS API: `Access-Control-Allow-Origin: *` для всех методов. Фронту CORS не нужен (один origin), достаточно `https://bee-dynasty.ru` и `:8443`, `:9443`.
- Swagger `/docs` открыт всем. Можно закрыть паролем в nginx на время конкурса или оставить открытым, но без пароля демо-учёток в описании.
- JWT живёт 21 день (`JWT_EXPIRE_DAYS`); на время конкурса хватит и недели.

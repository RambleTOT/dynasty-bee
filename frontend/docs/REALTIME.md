# Живые обновления (WebSocket)

Цель — чтобы участники узнавали о чужих действиях сразу, без обновления страницы и без ожидания опроса. Оператор отменил заявку — у диспетчера сразу тост «Оператор отменил №… — ждёт решения» и предложение на экране дня. Диспетчер принял — оператор получает ответ, инженер — новый маршрут.

| Часть                                               | Состояние                                                                                                                                 |
| --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Контракт для бэка: подключение, сообщения, события  | `docs/BACKEND_REQUESTS.md` п. 38                                                                                                          |
| Фронт: клиент, события → обновление и тосты         | готов, флаг `realtime` включён 29.09                                                                                                      |
| nginx сайта: `location = /api/v1/realtime/ws`, CSP  | выложено 29.09                                                                                                                            |
| Бэк: `/realtime/ticket`, `/realtime/ws`, публикация | 29.09 (`9dc3a17`): `plan.*`, `booking.created`, `booking.decision`, `engineer.action`, `request.status_changed`, `clock.changed`, `day.*` |

Пока флаг выключен или бэк не отвечает, всё работает как раньше — опросом (`POLL` в `config.ts`).

## Схема

```text
             REST-действие (как сейчас)
Оператор ───────────────────────────────► бэк ──► БД
                                            │ после commit: publish(событие, seq)
                                            ▼
                                   хаб событий бэка ── фильтр по роли и региону
                                            │ WebSocket /api/v1/realtime/ws
                 ┌──────────────────────────┼──────────────────────────┐
                 ▼                          ▼                          ▼
             диспетчер                   оператор                   инженер
     RealtimeClient → effects.ts: обновить запросы react-query пачкой + тост с «Открыть»
```

Действия по-прежнему идут через REST: сокет только сообщает, что изменилось. Данные фронт перечитывает теми же запросами, поэтому событие может быть коротким — номер заявки, план, регион, день.

## Модули

| Файл                            | Что делает                                                                                                                                                                                                                                      |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `api/realtime.ts`               | `POST /realtime/ticket` — одноразовый билет по токену; адрес `wss://<сайт>/api/v1/realtime/ws?ticket=…&since=…`. Токен в адрес не кладём: он попал бы в журналы                                                                                 |
| `realtime/protocol.ts`          | типы сообщений (`hello`, `event`, `ping`, `resync`, `error`) и безопасный разбор; незнакомое — пропускаем                                                                                                                                       |
| `realtime/client.ts`            | `RealtimeClient`: билет → сокет, переподключение, `since`, сторож тишины, повторы по `seq`, состояние                                                                                                                                           |
| `realtime/effects.ts`           | таблица «вид события → какие запросы обновить и какой тост показать» по роли; тост «ждёт решения» — только на чужое предложение (автор — `actor` или `data.source`), закрывается по `plan.applied` / `plan.rejected` того же плана и при выходе |
| `realtime/invalidationBatch.ts` | события за 250 мс — одним обновлением, каждый ключ один раз                                                                                                                                                                                     |
| `realtime/RealtimeProvider.tsx` | открывает сокет после входа и закрывает при выходе; тосты с «Открыть»; событие `online` — переподключиться сразу                                                                                                                                |
| `realtime/useRealtime.ts`       | `useRealtimeStatus()`, `usePollInterval(base)`: пока сокет открыт, опрос страховочный (`REALTIME.safetyPollMs`) — на случай потерянного события                                                                                                 |
| `config.ts`                     | `REALTIME` (паузы, сторож, пачка, страховочный опрос), флаг `FEATURES.realtime`                                                                                                                                                                 |
| `vite.config.ts`                | прокси `/api` с `ws: true` — сокет в dev идёт на бэк                                                                                                                                                                                            |
| `deploy/nginx/bee-dynasty.conf` | `location = /api/v1/realtime/ws`: `Upgrade`, `proxy_read_timeout 1h`, без буфера; `wss://` сайта в CSP `connect-src`                                                                                                                            |

Провайдер стоит в корне роутера внутри `AuthProvider` (`app/router.tsx`): ему нужны пользователь и роль, а тостам — переход по «Открыть».

## Жизненный цикл

1. **Вход.** `POST /realtime/ticket` → `{ticket}` → сокет с `?ticket=`.
2. **`hello`.** Состояние `open`. Опрос — `REALTIME.safetyPollMs`: пока бэк шлёт только события плана, не реже обычного (10 с); когда пришлёт всё из п. 38 — раз в 60 с. Номер `seq` в `hello` меньше нашего — сервер перезапускался: перечитываем всё и считаем номера заново (бэк в этом случае отвечает `resumed: true`).
3. **Событие.** Номер `seq` не больше последнего — повтор, пропускаем. Иначе `effects.ts` возвращает ключи запросов (обновляются пачкой через 250 мс) и, если нужно, тост.
4. **Обрыв.** Паузы 1, 2, 5, 10, 30 с (±20 %, чтобы вкладки не шли разом). Каждый раз новый билет и `since=<последний seq>`. Сервер присылает пропущенное (`resumed: true`). Если не может — `resumed: false` или `resync`, и страница перечитывает всё (`RESYNC_KEYS`).
5. **Тишина дольше 60 с** (сервер шлёт `ping` раз в 25 с) — соединение считаем мёртвым и переподключаемся.
6. **Выход** — сокет закрывается.
7. **Нет бэка.** Ручки билета нет (`404`, `405`, `501`) или роли сокет не положен (закрытие `4403`) — состояние `unavailable`. До перезагрузки больше не пробуем, работает обычный опрос.

## Что делает страница на событие

| Событие                                                       | Обновляет                                       | Тост                                                                                             |
| ------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `plan.proposed`                                               | день, план, поиск и окна оператора              | диспетчеру, если предложение не его: «Оператор отменил №10211 — ждёт решения», «Открыть» → DS-07 |
| `plan.applied`, `plan.rejected`, `plan.published`             | день, план, сравнение, экран инженера, оператор | —                                                                                                |
| `booking.decision`                                            | день, план, поиск и окна оператора              | оператору: «Диспетчер подтвердил отмену №…» / «…не принял отмену… — заявка остаётся в плане»     |
| `booking.created`, `booking.cancelled`, `booking.rescheduled` | день, план, оператор                            | —                                                                                                |
| `request.status_changed`                                      | день, план, экран инженера, поиск оператора     | —                                                                                                |
| `engineer.action`, `engineer.route_changed`, `clock.changed`  | день, план, экран инженера                      | — (инженер видит баннер «План изменён» из `/me/day`)                                             |
| `day.created`, `day.cleared`, `roster.changed`                | день, календарь, сценарий, оператор, инженер    | —                                                                                                |
| незнакомое событие с регионом или днём                        | день и календарь                                | —                                                                                                |

Ключи — префиксы из `api/queryKeys.ts`. Запросов, которых на экране нет, react-query просто не трогает, поэтому ключи не зависят от роли.

## Включение

1. Бэк сделал п. 38 и `POST /realtime/ticket` отвечает на стенде.
2. Флаг `realtime: true` в `FEATURE_DEFAULTS` (`config.ts`) или без правки кода — `VITE_FEATURES=realtime`.
3. Проверка на стенде в трёх вкладках (портов сайта три — 443, 8443, 9443, у каждого своя сессия):
   - оператор отменяет заявку в начатом дне → у диспетчера за секунду тост и баннер предложения;
   - диспетчер принимает → у оператора тост, у инженера баннер «План изменён», у диспетчера новая версия;
   - инженер нажимает «Выполнена» → статус на карте диспетчера меняется без обновления;
   - сеть выключили на 30 с и вернули → пропущенные события пришли (`since`), тостов не больше, чем событий;
   - бэк перезапустили → `resync`, день перечитан.
